# HUI-1701 文生图可信成功 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 服务端登记且哈希一致的夹具图可以在列表、详情和下载中打开；没有模型凭证时文生图仍失败关闭，并且不把完成写成已结算。

**Architecture:** `textimage.Admit` 做纯判定。只有状态完成、租户与工程一致、输入版本一致、登记哈希与文件字节一致、且来源是 fixture 时才展示。存储用单独的夹具登记写入 `completed`，通用更新仍拒绝把失败改成成功。HTTP 在开关打开时接受夹具字节，自己算哈希。计费沿用 `billassemble.Reconcile`，不调用预占、结算、释放。

**Tech Stack:** Go、SQLite、Next.js、现有 Button/Card/Badge。

**Spec:** `docs/superpowers/specs/2026-09-29-hui-1701-design.md`

## Global Constraints

- `charged` 为 JSON null。`billing_passed` 为 false。`production_authorized` 为 false。`production_authorization` 为 `NOT_AUTHORIZED`。
- 作品完成且无账单时结算文案是「作品完成待核对」。不要把 BillingPassed 设成 true。
- Hold、Release、Settle 不发送真实资金 HTTP。
- 真实出图文案是「真实出图未完成」。`real_generation_completed` 为 false。不生成模型图。
- 没有实物参考时不宣称主体保真。
- 测试命令带 `GOWORK=off`。不绑定 18101。
- 前端不新增组件库。
