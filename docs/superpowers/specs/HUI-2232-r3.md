# HUI-2232-r3 产品价值检查记录

日期：2026-09-30

总指挥已裁定。本包只记录一次产品价值检查。它不生成图片，也不通过产品价值门。入库记录的状态保持 `真实出图未完成`。

## 不做

- 不改 `videofixture`、`showcasevideo`、`httpapi`、`lightscene`、`textimage`、`go.mod`、`go.sum`。
- 不联网，不监听端口，不访问数据库，不调用供应商，不生成图片字节。
- 不把缺配置写成已检查，不把未知观测写成通过。
- 不把 `quality_passed`、`generation_passed`、`billing_passed` 写成 true。
- 不增加 `provider_calls`，不把 `charged` 写成 null 以外的值。
- 不把生产状态写成 `NOT_AUTHORIZED` 以外的值。
- 标准库以外的依赖不引入。生产代码禁止导入 `net`、`net/http`、`os/exec`、`database/sql`。

## 包与版本

唯一代码包：`server/internal/qualitygate`。

文档版本常量是 `product-value-check/v1`，写入 `schema_version`。调用方不能改版本。

## 输入

`Input` 字段：

- `LogicalID`、`TenantID`、`ProjectID`、`Digest`
- `Quality`、`Generation`、`Fee`（质量观测、生成观测、费用观测）
- `QualityPassed`、`GenerationPassed`、`BillingPassed`
- `Charged`（`*string`）、`ProviderCalls`、`Status`、`Production`
- `CallerPhrase`、`ImageBytes`

写入记录前去掉这七个文本的首尾空白：`LogicalID`、`TenantID`、`ProjectID`、`Digest`、`Quality`、`Generation`、`Fee`。摘要不做大小写折叠。观测也不做大小写折叠：`Unknown` 保持 `Unknown`。

逻辑编号：`LogicalID` 去空白后非空就用它；否则是租户、工程、摘要（均已去空白）用换行拼接后的 SHA-256 小写十六进制。观测、口径、旗标、扣费、图片字节都不进入编号。

## 配置缺失

租户、工程、摘要、质量观测、生成观测、费用观测，任一去空白后为空：返回错误文本 `配置缺失`，记录为 nil，不入库、不增加检查。此判断先于禁用短语，也先于回放。已入库的记录保持原样，这次不把它返回来。

## 拒绝

以下情况在编号尚未入库时：记录为 nil，不入库。错误文本是固定句子 `调用方口径被拒绝`，不回显调用方原文。

会被抄进记录的文本若包含禁用产出短语，就拒绝。抄进记录的文本只有：逻辑编号、租户、工程、摘要、质量观测、生成观测、费用观测。`CallerPhrase` 含禁用产出短语时同样拒绝，但这句口径本身不入库。

禁用产出短语只有这四句：`工程通过`、`质量通过`、`Billing PASS`、`真实出图完成`。`Billing PASS` 按小写后的 `billing pass` 做子串匹配，其余三句按原文子串匹配。

调用方把通过旗标设为 true、把 `charged` 设成非 null、把 `provider_calls` 设成非 0、把状态写成 `真实出图完成`、把生产写成别的词、或附上图片字节，都不是拒绝理由。这些值直接丢掉，不能翻转记录。

## 未知观测

`unknown`、`Unknown` 或其他非空且不含禁用短语的观测原文，去空白后写入记录并留下。未知不会被改成通过，也不会被丢掉。

## 接受时的记录

接受时返回一份新记录，字段固定为：

| 字段 | JSON 名 | 值 |
| --- | --- | --- |
| 版本 | `schema_version` | `product-value-check/v1` |
| 逻辑编号 | `logical_id` | 按上面的规则 |
| 租户、工程、摘要 | `tenant_id`、`project_id`、`digest` | 去空白后的原文 |
| 三条观测 | `quality`、`generation`、`fee` | 去空白后的原文 |
| 状态 | `status` | `真实出图未完成` |
| 质量通过 | `quality_passed` | false |
| 生成通过 | `generation_passed` | false |
| 计费通过 | `billing_passed` | false |
| 扣费 | `charged` | JSON null，不是 0，也不是空字符串 |
| 供应商 | `provider_calls` | 0 |
| 生产 | `production` | `NOT_AUTHORIZED` |
| 说明 | `notice` | `此记录不通过产品价值门` |
| 六枚标签 | `labels` | 见下，顺序固定 |

六枚标签按这个顺序，文本逐字如下：

1. `Engineering for the recorder test only`
2. `Browser NOT_RUN`
3. `Service NOT_VERIFIED`
4. `Billing NOT_VERIFIED`
5. `Production NOT_AUTHORIZED`
6. `Human UNKNOWN`

没有时间戳、随机数、图片字节或供应商调用。因此同一份输入每次得到同一份规范 JSON。`ImageBytes` 不进入记录。

## 回放

内存登记簿按逻辑编号保存记录。

必填字段都在、且该逻辑编号已经入库：返回与第一次规范 JSON 逐字节相同的副本，检查数保持 1。后一次即使带上禁用短语、试图把三枚旗标写成 true、或换一套观测，也不改已存记录，也不建第二次检查。副本与库内记录不共享切片，调用方改副本不能把库内结果改成通过。

第一次就被拒绝或因配置缺失未入库的编号，不会占位。之后若改成可接受的输入，才建立唯一一次检查。

## 规范 JSON

`CanonicalJSON` 使用 `encoding/json`，关闭 HTML 转义，去掉末尾换行，字段顺序与结构体声明一致。同一输入两次编码的字节相同。

nil 记录、或任何成功形态（状态不是 `真实出图未完成`、任一通过旗标为 true、`charged` 非 null、`provider_calls` 非 0、生产状态不是 `NOT_AUTHORIZED`、版本或说明或标签被改掉、必填文本为空、正文含禁用产出短语）都不编码。返回错误 `记录保持未完成` 和 nil 字节。错误文本本身不含四句禁用产出短语，也不回显调用方原文。

## 测试

测试在 `server/internal/qualitygate`，命令是：

```
cd server && GOWORK=off go test -count=1 ./internal/qualitygate/
```

不跑整个模块。

测试必须断言：`配置缺失`、`真实出图未完成`、三条观测会留下、`quality_passed` / `generation_passed` / `billing_passed` 为 false、`charged` 为 null、`provider_calls` 为 0、`production` 为 `NOT_AUTHORIZED`，以及上面的六枚标签。

测试必须检查接受记录和错误文本都不含四句禁用产出短语。拒绝路径和配置缺失路径的记录必须是 nil。调用方不能把 false 旗标翻转成 true。

## 证据

本包的记录不是产品价值门通过。状态是 `真实出图未完成`。生产保持 `NOT_AUTHORIZED`。
