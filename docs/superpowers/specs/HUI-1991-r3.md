# HUI-1991-r3 产品图消费端：服务端付款主体、人民币估价、不发送扣费

日期：2026-09-30

总指挥裁定是终稿。PR #14 与 #19 已经合入消费端和报价装配。本轮只延伸这条消费端，不建第二套钱包，不撤回 HUI-1701，不改光影失败关闭，不改画师。

## 不做

- 不在本产品建钱包、充值表、图像点数或第二份余额。
- 不让界面填写服务端未授权的付款人编号，不假装组织钱包。
- 不把 `charged=false` 当成资金证明。没有发出的扣费不是 `false`，而是 `not_sent` 或 `unconfigured`。JSON `charged` 为 null。`billing_passed` 为 false。`production_authorized` 为 `NOT_AUTHORIZED`。
- 不把生成成功写成已结算。没有真实模型凭证时文案仍是「真实出图未完成」。有服务端可信资产但没有结算时仍是「作品完成待核对」。
- 不改 HUI-1700 光影失败关闭。不购买模型，不改画师。服务商保持 NOT_VERIFIED。
- 不对客户资金扣款。未设置 `PRODUCT_BILLING_BASE_URL` 和测试令牌时，不调用现场计费服务。
- 不绑定或占用 18084、18120、8080、8081、5173，也不把 127.0.0.1:18101 当成计费或线索服务。

## 付款主体

身份已配置时，个人付款和已授权组织付款只由服务端从已验证身份解析。请求体里的付款人、租户或来源不能改付款主体。

身份或计费缺配置时，连接和展示都是「配置缺失」。适配器已经在进程里时，这不是「代码未实现」，也不是「未实现」。只有配置齐全但端口没装上，才是「未实现」。

## 报价

本产品只上报 `image_count`、`resolution`、`model`、`capability`、`pricing_version`。金额只来自计费端口返回的报价对象。

有报价对象时，展示估价「本次预计 ¥X.XX」或「已包含额度」。没有报价对象时不显示人民币金额。

夹具报价带 `quote_origin=fixture`。测试把夹具标成夹具，不把夹具标成 Billing PASS。

更换付款主体、模型、张数或尺寸会改变指纹。已经确认过的报价必须重新确认。确认本身不预占、不结算。

## 资金状态

- 身份或计费未配置，且没有发出扣费：`funds_state=unconfigured`。
- 配置或端口在，但本轮没有发送预占、结算或释放：`funds_state=not_sent`。
- 余额不足只给统一充值入口，不自动生成。从充值成功页返回只重读余额，不自动生成。
- 未知、响应丢失和重试挂回已保存的任务。不新开生成，不发送第二次扣费。

真实端口的预占、结算、释放仍不发送 HTTP。测试双可以在内存记下预占，并在用例结束前释放到净额零。这不是客户扣款。

## 租户夹具

A、B 两个租户夹具各自有余额。适配器按服务端租户和付款账号读取。A 的请求不能读到 B 的余额数字，反过来也一样。请求体里的租户不能换成对方。

夹具听在 `127.0.0.1` 的空闲端口，测完关掉。适配器与该夹具的对话只证明实现和这次集成。它不是 public-ai 的真实账本，Billing 保持 NOT_VERIFIED。渠道计费为 N/A。生产为 NOT_AUTHORIZED。

## 运行时标签和本轮证据

产品应答里的五级字符串保持：Implementation `PASS`，Integration `UNKNOWN`，Billing `UNKNOWN`，Channel `NOT_APPLICABLE`，Production `NOT_AUTHORIZED`。界面不把夹具对话写成 Integration PASS 或 Billing PASS。

本轮报告另记证据：适配器对上环回夹具则 Integration 为 PASS；没有真实 public-ai 账本轨迹则 Billing 为 NOT_VERIFIED。
