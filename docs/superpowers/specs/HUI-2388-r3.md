# HUI-2388-r3 选定产品图的版本化矩阵交接

日期：2026-09-30

总指挥裁定是终稿。本轮只在 `server/internal/matrixhandoff` 做版本化交接文档和夹具目录。不挂 HTTP，不做网页，不改计费、生成、光影、web 或 cmd。

## 不做

- 不把图片当成视频，不转码，不造假视频，不上传。
- 不扣客户的钱，不读取社交账号口令。
- 不说发布成功，不把草稿写成已发布。
- 不改产品图导出状态。本包不引用导出、存储或 HTTP 代码。
- 夹具编号不是 Service PASS。夹具客户端不是在线矩阵服务。
- 不宣称 Service、Billing、Production 或 Human 已通过。本包常量保持 Service `NOT_VERIFIED`、Billing `NOT_VERIFIED`、Production `NOT_AUTHORIZED`、Human `UNKNOWN`。

## 交接文档

从一张已选定的图片做出 `matrix-handoff/v1` 文档。文档带上：

- 资产编号、资产版本
- 内容哈希（64 位小写 hex）
- 质量结论 `pass`、`fail` 或 `unknown`
- 产品简报版本
- 许可
- 精确来源
- 来源上的 AI 披露（原样留下，不删）

媒体种类只能是 `image`。传入视频，或把同一资产编号当作已有视频，都拒绝。拒绝时不转码。

同一租户、品牌、资产编号和资产版本得到同一个草稿引用。引用由这四项决定，不随哈希或结论变化。内容哈希或保真结论变了，就追加新的草稿版本，旧版本保留，不覆盖。简报、许可、来源或披露变化同样追加，不改旧行。进程内记住版本；本包不写产品图库。

调用方已吊销则拒绝。调用方租户和图片租户不一致则拒绝。两种拒绝都不写入草稿，也不调用矩阵客户端。

## 夹具目录和矩阵接口

目录只描述夹具平台能收的内容类型：

| 夹具 | 内容类型 | 图片怎么处理 |
|---|---|---|
| `fixture.video_only` | 仅视频 | 只有图片、又没有已有视频资产时，结果是 `needs_video` |
| `fixture.article` | 文章 | 可以把图片当作插图收下 |
| `fixture.cover` | 封面 | 只有调用方同时给出另一个已有视频资产编号才收下 |

`needs_video` 不上传、不造视频、不把图片标成已发布，也不把这次结果写成 success。返回文案就是 `needs_video must not be described as success`。

封面没有已有视频资产时不接受，也不把图片编号伪装成视频。文章夹具接受插图时仍是草稿：不上传、不发布、不扣费。

矩阵是 `Client` 接口。`FixtureClient` 不是在线服务。客户端返回错误时，函数把错误交回去，草稿的发布状态保持未发布。客户端即使回了更好看的结论、`真实商品无改动` 或已发布，服务也不采用。

## 质量结论

`fail` 或 `unknown` 留在文档上，不改成通过。交给夹具时文案也不升级成 `真实商品无改动`。`fail` 的文案是 `fidelity fail must not become 真实商品无改动`。`unknown` 同样不得变成这句商品承诺。

## 证据边界

本包测试只证明进程内的文档、版本和夹具行为。Service `NOT_VERIFIED`。Billing `NOT_VERIFIED`。Production `NOT_AUTHORIZED`。Human `UNKNOWN`。浏览器不跑。
