# HUI-1701-r3 服务端任务的真实资产可以打开

日期：2026-09-29

总指挥裁定是终稿。PR #15 与 #20 已经合入失败关闭和夹具展示。本轮只修剩下的这一条：服务端自己持有的任务已经完成，并且带有真实资产编号时，刷新仍被改成 `unknown`、输出被清空、`show_image` 为 false。

## 不做

- 不改 HUI-1700 光影失败关闭。缺图像模型凭证不能变成光影成功。
- 不接受客户端自报的成功，也不接受请求体里的任意资产编号。
- 不把生成完成写成结算。没有真实结算轨迹时 `billing_passed` 与 `production_authorized` 保持 false，`charged` 为 JSON null。不宣称 Billing PASS。
- 不把没有实物参考的文生图写成主体保真。
- 不伪造平台任务成功。平台没返回成功，就不能写成成功。
- 没有可用的图像模型调用方式时，不拿凭证字符串冒充模型出图。本环境没有这种凭证。

## 可信完成

服务端轮询自己提交的任务。同时满足下面全部条件才展示：

1. 任务状态是平台的 `succeeded` 或 `completed`，不是客户端的 `success`。
2. 资产编号来自这次轮询结果里的 `platform_asset_id` 或 `asset_id`，不是请求体。
3. 字节由服务端取得并保存：任务结果里有能解码的 `data_b64`，或者没有这段载荷时由服务端调用本地测试出图。坏的 `data_b64` 不能改用本地图冒充。
4. 服务端计算 SHA-256，和文件字节一致。租户、工程、输入版本一致。
5. `origin` 为 `server`。夹具 `fixture` 仍按原规则展示。其它来源不展示。

缺资产、缺字节，或只有凭证字符串：保持 `unknown` 或原来的失败，`output_asset_id` 为空，`show_image` 为 false。凭证缺失本身不是成功。

失败记录不能被后来的成功改写。用户选定版本之后，晚到的另一资产不能覆盖。同一文字描述的幂等键返回同一条任务。

## 出图与文案

本地测试出图只在上面的可信完成里由服务端调用。它不是平台状态，也不是模型结果。`real_generation_completed` 为 false，文案保持「真实出图未完成」。没有照片时文案保持「概念输出，不宣称主体保真」。

有真实模型调用、费用和轨迹时才可以把服务商标成 PASS。本轮没有这种调用，服务商保持 NOT_VERIFIED。

完成且没有账单时，结算文案仍是「作品完成待核对」。不调用 Hold、Release、Settle。

## 界面

列表、详情和下载在判定通过时打开这张图。图片走本应用下载代理。面板不出现「已结算」。夹具文案保持「不是模型出图」。服务端任务图同样标明不是模型出图。
