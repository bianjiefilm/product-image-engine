# HUI-1702-r3 图生视频内存夹具

日期：2026-09-30

总指挥已裁定。本轮只新增版本化的内存夹具文档。已合并的失败关闭展示视频（PR #16，`cdf829f4e6dd4228eb58dc956a885cd77da53853`）保持不动。这个夹具不是真实视频。

## 不做

- 不改 `server/internal/showcasevideo`、`httpapi`、`web`、`store`、迁移、`go.mod`、`go.sum`。
- 不联网，不监听端口，不访问数据库，不调用供应商，不生成视频字节。
- 不把静图、占位地址、空字节声明或调用方的成功口径写成成功。
- 不把 `show_video`、`play_still` 写成 true，不填写 `video_url`。
- 不增加 `provider_calls`，不把 `generation_triggered` 或 `billing_passed` 写成 true，不把 `charged` 写成 null 以外的值。
- 不把生产状态写成 `NOT_AUTHORIZED` 以外的值。
- 标准库以外的依赖不引入。

## 包与版本

唯一代码包：`server/internal/videofixture`。

文档版本常量是 `image-to-video-fixture/v1`，写入 `schema_version`。调用方不能改版本。

## 输入

`Input` 字段：

- `RequestID`、`TenantID`、`ProjectID`、`ImageDigest`
- `Still`、`MediaType`
- `PlaceholderURL`
- `ByteCount`（`*int`，nil 表示没有字节声明）、`ClaimedBytes`（nil 表示没有字节声明）
- `CallerPhrase`

写入文档前去掉这四个标识的首尾空白：`RequestID`、`TenantID`、`ProjectID`、`ImageDigest`。摘要不做大小写折叠。

逻辑请求编号：`RequestID` 去空白后非空就用它；否则是租户、工程、摘要（均已去空白）用换行拼接后的 SHA-256 小写十六进制。成功口径、地址和字节不进入编号。

## 配置缺失

租户、工程、摘要任一去空白后为空：返回错误文本 `配置缺失`，文档为 nil，不入库、不增加任务。此判断先于静图、地址、字节和口径。

## 拒绝

以下情况文档为 nil，不入库，不得变成成功。错误文本是固定句子，不回显调用方原文：

- 静图：`Still` 为 true，或 `MediaType` 去空白并小写后以前缀 `image/` 开头。错误 `静图不能当成视频`。
- 占位地址：`PlaceholderURL` 去空白后非空。任何这类地址都不是视频地址。错误 `占位地址不能当成视频`。
- 空字节声明：`ByteCount != nil && *ByteCount <= 0`，或 `ClaimedBytes` 非 nil 且长度为 0。错误 `空字节声明被拒绝`。
- 调用方声称视频已经成功，或标识字段含有禁用产出短语。错误 `调用方口径被拒绝`。

声称成功的口径：包含 `成功`、`可播放`、`真实出图完成`、`图生视频成功`；大小写不敏感地包含 `billing pass`、`success`、`succeed`、`completed`；整句（去空白、小写）是 `pass`、`passed`、`done` 或 `ok`。

会被抄进文档的标识若包含禁用产出短语，同样拒绝，避免短语进 JSON。禁用产出短语只有这四句：`图生视频成功`、`可播放`、`Billing PASS`、`真实出图完成`。大小写不敏感地匹配 `billing pass`。

正数字节声明或 `video/*` 媒体类型都不是成功。字节不进入文档。`provider_calls` 仍是 0，`generation_triggered` 仍是 false，`show_video` 仍是 false。

## 接受时的文档

接受时返回一份新文档，字段固定为：

| 字段 | JSON 名 | 值 |
| --- | --- | --- |
| 版本 | `schema_version` | `image-to-video-fixture/v1` |
| 逻辑请求编号 | `request_id` | 按上面的规则 |
| 租户、工程、摘要 | `tenant_id`、`project_id`、`image_digest` | 去空白后的原文 |
| 状态 | `status` | `真实视频未验证` |
| 画面 | `show_video`、`play_still` | false、false |
| 地址 | `video_url` | 空字符串，键保留 |
| 供应商 | `provider_calls` | 0 |
| 生成 | `generation_triggered` | false |
| 结算 | `billing_passed` | false |
| 扣费 | `charged` | JSON null，不是 0，也不是空字符串 |
| 生产 | `production_status` | `NOT_AUTHORIZED` |
| 是否真实视频 | `real_video` | false |
| 说明 | `notice` | `夹具不是真实视频` |
| 六枚标签 | `labels` | 见下，顺序固定 |

六枚标签按这个顺序，文本逐字如下：

1. `Engineering`
2. `Browser NOT_RUN`
3. `Service NOT_VERIFIED`
4. `Billing NOT_VERIFIED`
5. `Production NOT_AUTHORIZED`
6. `Human UNKNOWN`

没有时间戳、随机数或字节载荷。因此同一份输入每次得到同一份规范 JSON。

## 回放

内存登记簿按逻辑请求编号保存文档。

同一逻辑请求编号再次提交：返回与第一次规范 JSON 逐字节相同的副本，任务数保持 1。后一次即使带上成功口径、静图、占位地址或空字节，也不改已存文档，也不建第二个任务。副本与库内文档不共享切片，调用方改副本不能把库内结果改成成功。

第一次就被拒绝的编号不会入库。之后若改成可接受的输入，才建立唯一任务。

## 规范 JSON

`CanonicalJSON` 使用 `encoding/json`，关闭 HTML 转义，去掉末尾换行，字段顺序与结构体声明一致。同一输入两次编码的字节相同。

nil 文档、或任何成功形态（状态不是 `真实视频未验证`、画面开关为 true、地址非空、`provider_calls` 非 0、`generation_triggered` 或 `billing_passed` 为 true、`charged` 非 null、生产状态不是 `NOT_AUTHORIZED`、`real_video` 为 true、说明或标签被改掉、正文含禁用产出短语）都不编码。返回错误 `夹具保持未验证` 和 nil 字节。错误文本本身不含四句禁用产出短语。

## 测试

测试在 `server/internal/videofixture`，命令是：

```
cd server && GOWORK=off go test -count=1 ./internal/videofixture/
```

测试必须断言：`配置缺失`、`真实视频未验证`、`show_video`/`play_still` 为 false、`video_url` 为空、`provider_calls` 为 0、`generation_triggered` 为 false、`billing_passed` 为 false、`charged` 为 null、`NOT_AUTHORIZED`，以及上面的六枚标签。

测试必须检查接受文档和错误文本都不含四句禁用产出短语。拒绝路径的文档必须是 nil。
